# 取得後の差分更新（2026-11-03）

Overpassのクエリ、ズーム14の取得・キャッシュ単位、取得済み判定、データ保持上限は変更していません。

- POI/Activityデータの世代・参照、表示範囲、ズーム、階、言語、一覧設定が同じなら、一覧の元行を再利用します。カテゴリ・キーワード・個人フィルタはその都度適用します。
- 通常の施設一覧では、表示行・状態・表示設定が同じ場合はDOM更新を省略します。一部だけ変わった場合は、変更のない行のDOMを再利用し、スクロール位置を保持します。
- 専用ビュー、新着・お気に入り・履歴モード、検索・発見機能の装飾が有効な一覧は、従来の描画経路を維持します。
- カテゴリ候補はPOI全行のJSON化・復元をやめ、値ごとに集約してから挿入します。
- マーカーのGeoJSONが前回と同じ場合は、MapLibreの同じソースに再送信しません。ソースが再作成された場合は必ずデータを設定します。
- ポリゴンを点マーカーに変換するときは、破棄する頂点列を複製せず、属性と代表座標を複製します。元の地物の形状・属性を保持します。
- 画像欄と3D表示は既存の重複更新抑止を維持しています。

初回取得の通信量やOverpass待ち時間は変わりません。地図移動で表示対象が変わる場合や、新規データが届く場合に必要な計算は引き続き行います。

検証: `node tests/run.cjs`。追加した `tests/listtable-diff-render.cjs` は1,200行を使い、同一更新、状態変更、移動・ズーム・階・同一IDの内容変更、カテゴリ・キーワード変更を確認します。`tests/poi-favorite-marker.cjs` では同一ソースへの再送信抑止、表示範囲からの出入り、背景スタイルの再作成、5,000頂点の形状保持を確認します。

## viewAreaとインドア判定の追加対策

2026-11-03に以下を追加しました。

- 屋内の部屋・壁・通路などがない範囲では、成立しない建物ベースのインドア判定を早期終了します。
- 候補建物のPOI存在確認は1件見つかった時点で打ち切り、全地物の所属判定は採用した建物に限定します。
- 地下POIがない場合は、全地物の輪郭から距離を計算しません。地下POIがある場合も、半径内に入り得る対象へ絞ってから正確な距離を計算します。
- 同じ形状とデータ世代で境界矩形を再利用します。タイル建物にIDがある場合は、ID生成用の全座標JSON化を省きます。
- 同じ階の同じデータをMapLibreへ再送信せず、同じ階選択UIの再生成も省略します。地物の更新、階変更、背景ソースの再作成時は更新します。

取得クエリや取得済みタイルの判定は変更していません。

`viewArea` が100ms以上かかった場合は、コンソールに `viewArea: slow update` と、対象・準備・階層判定・描画の所要時間を記録します。
`tests/indoor-performance.cjs` は屋外12,000件で不要な交差演算が走らないことと、地下・建物・重なる建物の選択、境界の無効化、階ソースの更新を確認します。

## 移動時の取得予約

- 地図の移動終了から300ms静止してから更新します。連続操作は最後の表示範囲にまとめます。
- 更新中に移動した場合は、最後の位置だけを予約します。更新完了時に既に300ms静止していれば、追加の300ms待機はしません。ドラッグ中は次の取得を開始しません。
- 進行中の取得は中断せず、取得した応答を既存のキャッシュとPOIデータへ保持します。次の位置が予約されている場合は、古い位置の一覧・地図描画を省略します。
- 初期表示、カテゴリ変更、明示的な再読込は300ms待機の対象外です。進行中の更新がある場合は完了後にまとめて実行します。
- Overpassのクエリ、ズーム14のキャッシュ単位・キー・有効期限・取得済み判定は変更していません。

`tests/map-move-scheduler.cjs` は制御した時刻と取得応答で、連続移動、取得中の移動、静止済み・ドラッグ継続、取得失敗、応答保持、明示的な更新と再読込の直列化、低ズーム時の取得抑止を確認します。
